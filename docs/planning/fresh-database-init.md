# Explicit fresh-database initialization (unreleased app contract)

This is a separate, operator-invoked path for an **already empty** PostgreSQL database. It does not create, drop, truncate or reset a database and never adopts an existing schema. It is not a flag on `bootstrap-db`, `migrate`, or the predecessor-bound disposable replacement. Nothing in this document authorizes a production operation.

- Run the *candidate* `server fresh-init-db --confirm-empty` only with a bootstrap-superuser connection to the named target. For a stamped candidate, `APP_VERSION` and `GIT_SHA` must match the binary release contract and its fixed database name. The command rejects a missing flag, an unknown database, any public relation/extension, or any non-system schema before it changes roles or schema. Missing app, migration, media-cleanup or data-retention credentials also fail before DDL. It uses the same environment/config role names as `bootstrap-db`: `APP_DB_USER`/`APP_DB_PASSWORD`, `MIGRATION_DB_USER`/`MIGRATION_DB_PASSWORD`, `MEDIA_CLEANUP_DB_USER`/`MEDIA_CLEANUP_DB_PASSWORD`, `DATA_RETENTION_DB_USER`/`DATA_RETENTION_DB_PASSWORD`, plus the bootstrap `DATABASE_URL` (or existing `BootstrapDatabaseURL` config). The host owner supplies those values without exposing them in logs; this branch does not edit host configuration.
- The app command installs the existing role/ACL bootstrap, applies the embedded fresh baseline plus forward migrations and hardening under the migration role, checks the real schema and 77-entry ledger, then records a private superuser-owned, migration-read-only fresh-init receipt bound to database, stamped identity and inventory digest. The receipt is NOT the predecessor-reset completion. A failed partial run on a now nonempty DB refuses retry and requires separately reviewed recovery; never automatically wipe or reinterpret it as v1.25.9.
- Existing stamped `bootstrap-db` and `migrate` accept only a valid private fresh receipt *and* exact actual ledger/schema, or retain their pre-existing disposable predecessor/completion checks. An invalid present fresh receipt is a hard stop, not fallback. The generic host release sequence still needs SRE integration; do not run it against an empty DB assuming it invokes this command.
- The owner/operator must supply an actual administrator name, email, date of birth and password via the existing `admin create --email ... --name ... --date-of-birth YYYY-MM-DD` secure CLI and `MYCFC_ADMIN_PASSWORD_FILE` (or its interactive terminal input). Do not put these in shell history, source, chat or logs. Verify that the resulting active adult ADMIN can authenticate and reach an authorized page before any route switch. The app does not invent an identity/password or turn a synthetically created test account into a production custodian. This is a separate custody decision, not a reason to omit the tested app path.
- The owner has separately authorized losing historical production member/event/training/publication records by a production DB delete/recreate; that operation has NOT happened here. Uploads and unrelated infrastructure remain untouched. SRE owns the exact host Compose/env compatibility and release sequence, including maintenance routing, backup/restore decision, and no-old-binary fallback. No live DDL, database reset, secret inspection, publication, merge or deployment occurs from this branch.

Real local evidence: a dedicated disposable PostgreSQL container ran the stamped candidate `fresh-init-db` against an empty `mycfc` database; 77 ledger markers matched `41eca3f0ca37f6e6ba5279fe1d931ff589de72b2a8586a77e31445e8a8b29ed7`, four login roles existed, and the existing `cmd/admin create` made a synthetic adult ADMIN with a bcrypt hash. Missing flag/maintenance credential, predecessor-bound `bootstrap-db` on empty, nonempty retry and tampered-ledger `bootstrap-db`/`migrate` refused; stamped bootstrap/migrate on a valid fresh receipt succeeded. A separate opt-in Go integration test exercises unapproved nonempty-table preservation, role/schema/ledger postconditions and retry denial. These are local tests, not production acceptance.
