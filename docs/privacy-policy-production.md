The closed v2 catalogue covers the 22 existing server-defined internal categories. It preserves the approved 90-day identifying case-work period, one-month response and two-month extension windows. Identity, health, relationships and personal participation data are handled during execution; object-version cleanup has the approved 30-day maximum. Consent evidence expires three calendar years after cessation; consent network evidence after 12 months; minimal request and restore evidence after 24 months; logs and outbox metadata after 90 days; sessions after their existing maximum 12-hour clock. The existing executor applies the separate shorter delivery, token and payload clocks. Ordinary offboarding retention is not reinterpreted as an extension of approved erasure deadlines.

`review_after` is an operational review bound capped at the earlier of one year or the category's own expiry. It uses each category's existing calendar unit and lifecycle anchor. The annual governance-review date is separate from those per-record clocks and the existing 90-day technical activation-evidence expiry. `APPROVED_POLICY` is the server's provenance code for the adopted internal rules; it does not invent a statutory legal ground.

No exception grounds are included. Fiscal/payment, insurance/incident, liability, federation and non-consent health exceptions cannot be inferred from the waiver of extra documents. If an actual case needs one, the current catalogue rejects that retention decision; exact category fields, grounds and periods require a separately approved policy version. Unsupported future providers remain excluded. The declared complete empty provider inventory still requires the independent technical artifact; this JSON does not manufacture it.

Production import, grants, release and activation remain later GitHub-controlled operations. `ProductionPolicyArtifact` exposes independent canonical bytes plus their digest for the future operator; `ProductionPolicy` validates the embedded file against the same existing v2 rules. Tests compile a complete account-closure plan, reject an unapproved legal hold, check all lifecycle periods and canonical formatting, and pass the file through the existing strict import parser. Changing the adopted catalogue requires a new version; do not edit this version in place after adoption/import.
