# Week workspace browser acceptance (#398)

Run the isolated opt-in suite against a frozen application checkout:

```sh
python3 e2e/run-week-workspace.py /tmp/mycfc-week-workspace-evidence
```

`--app-source /path/to/frozen/source` can compile another checkout while reading these new tests from the current checkout. Docker, Go and npm are prerequisites. Evidence must be a new directory outside source checkouts; it is created with mode 0700. This runner neither changes nor runs the existing group or season suites.

The runner creates its own PostgreSQL 16.9 container and loopback ports, using Europe/Lisbon and the full fresh baseline plus migration ledger. Browser dependencies come from the exact existing lockfile; Playwright 1.63.0 runs as the caller's UID/GID with read-only source and dependency mounts, one worker and zero retries. Application/cloud secrets are not inherited from the caller. Success and failure stop the owned app/attacker servers and remove only owned containers and anonymous volumes, with cleanup evidence.

All identities, dates, appointment times, instructions and routines are synthetic. The first fixture has no season or week and verifies contextual missing-season help without silently provisioning dates. A second fixture supplies two different seven-day shapes, including two afternoon appointments, Saturday morning work, explicit timed rest, genuinely unplanned bands and a stored cancelled session. These explicit times are not inferred from the private plans. Fixture provisioning does not establish the complete #404 setup or acceptance of the supplied training content.

The suite checks desktop seven-day rendering and native mobile day/week navigation; a selected session retaining the complete overview; actual empty-roster draft week/session creation and exact returned IDs; blank initial times; cancel, Back, refresh, linked validation and contextual errors; bounded group/week/session context; filtered routine results retaining an empty selected day; contextual advanced options; real never-published/current/changed states; selected-week review with prospective counts labeled `previstas`; and preservation of stored publication/prescription/outcome bytes during navigation and draft edits. Publications are created through the real UI/engine. An outcome is explicitly fixture-seeded afterward for preservation checks.

Unavailable publication reads are a documented disposable database fault injection: the publications table is temporarily renamed while the actual application serves the route, then restored in a `finally` block before historical comparisons. No application test switch, mocked view model, protocol stub or fake UI is used for this state. It must render an unavailable state without claiming draft/publication certainty or offering a publish mutation.

A file handshake applies fixture grant revocation only after the browser holds a real rendered native form. Its POST and subsequent GET must recheck current authority. A separate loopback origin serves only one attacker form and requires actual Origin/Fetch Metadata denial with the authenticated cookie present. Early denied responses must retain private headers. Feature-disabled requests remain denied.

Actual route axe analysis fails on serious/critical findings; native keyboard focus, explicit ARIA feedback and horizontal overflow are checked at 320px and desktop. No-JavaScript paths are exercised separately. Screenshots support visual review. Automated checks do not establish manual screen-reader, real zoom, forced colours/reduced motion or coach observation; publication conflict tests also do not complete #403's future review design. There is no source-plan import, cadence interpretation, new scheduling precision, merge, deployment or production mutation in this work.
