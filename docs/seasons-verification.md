# Season setup browser verification (#394)

Run only the isolated season acceptance suite:

```sh
python3 e2e/run-seasons.py /tmp/mycfc-seasons-evidence
```

The evidence directory must be new, outside source checkouts, and is created with mode 0700. An optional `--app-source /path/to/frozen/source` compiles another checkout while reading these new test files from the current checkout. This command does not run or change the twelve group acceptance cases. Docker, Go and npm are required. Exact lockfile dependencies are installed into the evidence directory; the browser is pinned Playwright 1.63.0, runs as the caller's UID/GID, and mounts test source and dependencies read-only. The spec is opt-in and skipped by ordinary browser runs.

The runner provisions a unique PostgreSQL 16.9 container bound to loopback, in Europe/Lisbon, with the complete fresh baseline and migration ledger including `reset-baseline-v1`. It uses only synthetic users and creates no season in the initial SQL fixture. Repeated member GETs must leave that empty season state unchanged while profile and deactivation actions remain usable. All season creation, preview and selection then use actual native forms and application routes. A second SQL phase provisions synthetic historical membership, group, week, publication and prescription records so exact returns and historical invariance can be checked. This seeding is fixture provisioning, not evidence for the complete #404 initial setup or a publishing journey.

Covered behavior includes explicit date inputs without defaults, invalid and reversed dates, duplicate codes, equal leap-day endpoints, creation without current selection, separate preview and confirmation, current-list state, stale preview/replay rejection, altered token/context recovery, exact member collection/classification/group-week/definition return contexts, unauthorized coach POSTs, actual cross-origin authenticated native POST rejection, and season availability while structured planning is disabled. Actual route axe checks cover serious/critical findings, mobile 320px and desktop layouts, keyboard focus and linked validation feedback. Native no-JavaScript creation and confirmation are exercised separately from axe injection.

The installed CSRF middleware uses Fetch Metadata/Origin. Its negative test sends an authenticated native form from a separate loopback port and requires a different Origin, a sent session cookie, denial and no database change. The attacker fixture serves only a fixed form, never evidence files or mocked application pages.

This suite deliberately takes approximately fifteen minutes: it captures an unaltered real signed preview, records the signed deadline, runs the other cases, then waits for the real wall clock to pass that deadline in the same server process. It does not change server/database/browser time, mint signed test tokens, expose the process signing key or add a production test switch. The expiry case submits the original token, requires rejection, and follows a fresh review path. This elapsed token deadline is unrelated to future placement dates or a Lisbon midnight rollover.

Evidence remains outside the checkout: JSON reports, axe output, screenshots, failure traces, source/test manifests, binary hashes, retained-history snapshots and expiry deadline/wait state. One worker and zero retries are used. Success and failure paths stop both owned local servers, remove only the owned containers/volumes and record port cleanup. Failed harness iterations remain failed evidence. Manual screen-reader behavior, real browser zoom, coach observation, full #391/#404 acceptance, merge, deployment and production data changes are not established by this suite.
