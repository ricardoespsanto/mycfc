# #336 sporting taxonomy — local DB/sqlc slice

The new write vocabulary is `sporting_modalities` (Canoagem, Kayak Polo, SUP), `canoe_craft_classes` (K1/K2/K4/C1/C2/C4), `person_sporting_modalities` and `person_canoe_craft_classes`. Person assignments are independent of the dated `user_memberships` programme row. sqlc exposes scoped additive writes (`AssignScopedSportingModality`, `AssignScopedCanoeCraftClass`) for active administrators or coaches with a current matching programme/team grant. Invalid sports/crafts fail by FK/check; a craft requires its Canoagem parent assignment. The new classification never joins platform roles or grants to confer authority. A season-locked team trigger refuses a second Kayak Polo team, and migration refuses existing duplicates without deleting or reconciling teams. pt-PT labels are in the new catalog queries; no staff form is included here.

## Legacy consumer inventory (unchanged, deliberately)

- `modalities` and `membership_modalities` still contain K/C and SUP legacy IDs. `GetModalityByCode`, `AddMembershipModality`, `ListModalitiesForMembership`, WhatsApp modality audiences, announcement targeting, `ListAnnouncementModalities`, competition documents and `ListCompetitionDocumentsForMember` still read/write those IDs. Do not present that catalog as the new top-level sport choices.
- `training_sessions.modality_id`, `competition_documents.modality_id`, `announcements` audience links and `training_variation_groups.craft_modality_id` retain legacy FK identities. `ListStructuredCrewModalities` and `structuredCrewSize` still use those craft IDs; #337 should switch the selector to explicit K2/C2/K4 codes and audit all crew writes. No FK, published prescription snapshot, event, document, or training row is repointed here.
- `user_memberships.team_id` and team audiences retain team identity. The new one-team guard only constrains Kayak Polo; the existing programme/season FK continues to validate membership team scope.

## Deferred acceptance / integration risk

This is **not full #336**: this follow-on adds `SportAssignmentService.Replace` for a complete desired sport or craft selection, with transactional current Lisbon-date coach scope (or active administrator), fixed code validation, append-only per-change actor/reason/grant audit and explicit craft removal audit on Canoagem removal. Empty selections remove all; unchanged selections do not create events. The old additive `AssignScoped...` sqlc calls remain compatibility-only and **do not produce this correction audit**; #338 must call the service for editable staff forms, not direct sqlc assignments or table DML. This is server-side only: no HTTP handler/form, no database-level prevention of privileged direct table writes, and no configurable season definitions/escalões. #339 must transition current audience/announcement/document reads away from `membership_modalities` without retargeting historical rows, and define time semantics for person-sport assignments if historical sport eligibility becomes relevant. #337 still owns the crew selector and temporary crew taxonomy. Existing legacy write APIs remain for compatibility and must not be offered as new classifications. Classification alone does not implement publication or programme access.
