# Implementation status

This document records the current implementation boundary. Planned and deferred work is tracked in the [MyCFC Delivery Project](https://github.com/users/ricardoespsanto/projects/1).

| Specification | State | Notes |
|---|---|---|
| 00 System context | In progress | Repository boundaries, module, config, HTTP foundation and local workflow exist; a public CFC landing page with locally embedded imagery, contacts, account calls to action, and club-site links is available at `/`. |
| 01 Data models | Implemented source | Reset-only baseline schema, queries, sqlc config and transaction helper are present; season memberships, teams, modalities, and director-approved annual categories are modelled with PostgreSQL integration coverage. |
| 02 Routing and middleware | Implemented foundation | Full route table is registered; business handlers remain deliberately unavailable rather than returning fake success. |
| 03 Dashboards | Partial | A shared Hoje view shows events visible through active memberships, dependent responsibility, coach scope, or administration. Navigation exposes separate leisure, initiation-athlete, competition-athlete, kayak-polo-athlete, guardian, coach, moderator, and administrator fleet workspaces from active memberships and delegated grants; teams and programmes are not authentication roles. Membership-programme dashboards provide competitor metrics/training/groups and leisure news/groups; every adult account can manage dependants, and platform administrators can access fleet/repair/maintenance visibility. Administrators can draft, schedule, publish, and expire news using the existing `news_items` table; scheduled items become visible at their publication time. Shared events support administrator authoring, programme/team targeting, RSVP, capacity/waitlist, guardian responses, confirmation and check-in. Targeted announcements support programme, team, category, modality, event, and guardian audiences, draft/publish/expire lifecycle audit, and delivery on first visibility/read on detail; there is no internal chat. The Treinos workspace persists scoped plans and sessions, validates active-membership assignments, lets only the assigned athlete record completion, and retains historic logs and metrics as read-only history. It also publishes curated official competition documents with a HTTPS link, source, review date, event/modality context and membership-based visibility; modality documents must have a programme or team scope. Scoped coaches can author only in their programme/team/event grant; administrators have club-wide authoring. Club operations owns the dashboard read models through the controlled CLI/import boundary in `docs/dashboard-data-provisioning.md`; populated-state acceptance requires a successful import. Public calendar fallbacks remain available where relevant. Club information has no existing editable source: configuration only supplies external service and legal-document links, and no schema migration or alternate persistence was added. Public club information therefore remains deferred until a live schema change is approved. |
| 04 Repair workflow | Partial | Repair reporting with multipart validation, idempotency, private object storage, and administrator visibility exists. Administrators can move repairs from pending to analysis and then resolution, and complete maintenance tasks; the existing repair status, `updated_at`, `resolved_at`, and maintenance status, `completed_at`, `updated_at` fields record those changes. The actor for a repair status change or maintenance completion, a reason, and immutable status-history audit records require an approved live schema change and are not persisted. PostgreSQL concurrent idempotency and MinIO encrypted upload/delete integration coverage plus no-JavaScript browser photo upload and same-key retry evidence exist. |
| 05 Authentication and consent | Partial | Login, generic adult registration, guardian dependant creation with transactional responsibility consent, configuration-backed legal-document links, database-backed current-user loading, membership and platform-admin guards, logout, and administrator CLI exist; account sessions contain only identity. Credentialed minors use a club-issued `CFC-` identifier, never email registration; issuance and recovery require an active named guardian relationship and active administrator, atomically update credentials, and append an audit record. Minors are barred from guardian, administrator, and staff controls. The operator CLI grants and revokes append-only-audited coach programme/team and future moderator grants with an explicit active-admin actor; they are distinct from platform-admin grants and do not authorize fleet access. |
| 06 Accessibility/localisation | Partial | pt-PT locale helpers and HTTP error text exist; Playwright covers registration keyboard navigation, keyboard logout, and responsive competitor/guardian flows, while full page-state accessibility checks remain. |
| 07 AWS deployment | Implemented source | Terraform bootstrap and production foundations cover state, private network, RDS, S3, ECR, ALB/WAF, ECS, and GitHub OIDC; operator values and live AWS plan/apply evidence remain. |
| 08 GitHub Actions | Implemented source | Pinned CI, infrastructure, deployment, and Dependabot workflow foundations exist; protected environment configuration and live execution remain. |
| 09 Local development | Implemented source | Compose, env template, Air config and Make targets are present. |
| 10 Acceptance matrix | In progress | `docs/acceptance-matrix.md` maps the implemented workflows to unit, PostgreSQL/MinIO integration, and configured Playwright/axe evidence. It also records the remaining browser, accessibility, and environment-dependent gaps without treating them as covered. |

Training plans and sessions are scoped to teams or programmes, with teams preferred as the existing group model. Sessions are visible from active matching memberships without individual assignment. Athletes report `COMPLETED`, `MISSED`, or `REPLACED` outcomes; a replacement must identify another visible session and a short reason. Staff attendance and check-in are not part of the training workflow.
